How the Web Works

A plain-English walkthrough of everything from class — with a simple, everyday analogy next to every technical explanation, so it clicks whether you've never touched code or you're already comfortable in a terminal.

By the end of this topic you should be able to: explain client vs. server, read a URL, recognise HTTP methods and status codes, tell HTML/CSS/JS apart, have Node/Git/Live Server installed and verified, serve a page correctly (not as a file://), and use DevTools' Console + Network tabs without help.
Concept 01

Client & Server

Every website you have ever used is really a conversation between two computers: one that asks for something, and one that answers.

Layman's example

Think of a restaurant. You (the customer) sit down and tell the waiter what you want. The waiter walks to the kitchen, the kitchen prepares it, and the waiter brings the food back to you. You never go into the kitchen yourself — you just make a request and receive a response.

Technical definition

The client (your browser) sends an HTTP request to a server (a computer running somewhere else, often in a data centre). The server processes it — maybe talking to a database — and sends back an HTTP response, usually HTML, CSS, JS, or JSON data.

Who plays which role?

You (customer)
orders food →
Waiter (browser)
request →
Kitchen (server)

What actually happens when you open a site

  1. You type example.com in the address bar.
  2. The browser asks DNS ("Domain Name System" — think of it as the internet's phone book): "What is the IP address for example.com?"
  3. DNS replies with an IP address, e.g. 93.184.216.34.
  4. The browser sends HTTP GET / to that address.
  5. The server replies 200 OK plus the HTML, CSS, and JS.
  6. The browser draws ("renders") the page on your screen.
Debugging habit for the whole course Whenever something breaks, first ask: is this a client problem or a server problem? A blank white page with a JS error in Console is usually a client problem. A page that never loads and shows a 500 status is a server problem.

Role reference table

RoleRuns whereTools used in this course
Client (frontend)Inside the user's browser, on their own deviceHTML, CSS, JavaScript, React
Server (backend)A computer somewhere else (a remote machine / data centre)Node.js, Express, MongoDB

Note: React runs on the client. Express runs on the server. They only ever talk to each other over HTTP — never directly.

Concept 02

Anatomy of a URL

Layman's example

A URL is like a full postal address. It says how to deliver the letter (protocol), which building (host), which door of that building (port), which room inside (path), any special instructions attached to the delivery (query), and where exactly to place it once you're inside the room (fragment).

Technical definition

A URL (Uniform Resource Locator) is a structured string that a browser parses into distinct parts, each telling the networking stack something different about how and where to fetch a resource.

https://api.example.com:443/products/42?sort=price#reviews
protocol — how to talk host — which computer port — which door path — which page/resource query — extra options fragment — spot on the page (browser-only)
PartMeaningNotes
httpsProtocolEncrypted HTTP — always use it in production
api.example.comHostDNS turns this into an IP address
:443PortOften hidden. 80=HTTP, 443=HTTPS. 5500/5173 = your local dev servers later.
/products/42PathWhich specific resource you want
?sort=priceQueryExtra parameters; & joins more of them
#reviewsFragmentBrowser-only — never sent to the server
Easy to confuse The fragment (#reviews) looks like part of the address, but the server never even sees it — it's purely used by the browser to scroll to a section on the page you already loaded.
Concept 03

HTTP Methods & Status Codes

Layman's example

Methods are like the verb in a sentence you say to the kitchen: "bring me the menu" (GET), "add this new dish" (POST), "change this dish" (PUT/PATCH), "remove this dish" (DELETE). Status codes are the waiter's one-line reply: "here you go" (200), "sorry, we don't have that" (404), or "the kitchen caught fire" (500).

Technical definition

An HTTP method tells the server what operation to perform on a resource. A status code is a 3-digit number the server returns describing the outcome of that request.

Methods

MethodMeaningReal example
GETReadLoad a page or a product list
POSTCreateSubmit a signup form
PUT / PATCHUpdateEdit your profile
DELETERemoveDelete a to-do item

Status codes worth memorising

RangeMeaningCommon examples
2xxSuccess200 OK, 201 Created, 204 No Content
3xxRedirect / cache301 Moved Permanently, 304 Not Modified
4xxYour request is wrong400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
5xxThe server failed500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable
Habit for the whole course 4xx → fix the request (you sent something wrong, e.g. mistyped URL or missing login). 5xx → fix the server (the backend code or infrastructure is broken — not something you can fix from the browser).
Concept 04

The Three Web Languages

Layman's example

Imagine building a house. HTML is the walls, rooms and doors — the raw structure. CSS is the paint, furniture and décor — how it looks. JavaScript is the electricity and smart switches — what happens when you interact with it (turning on a light, opening a garage door).

Technical definition

HTML defines structure and meaning, CSS defines presentation, and JavaScript defines behaviour — dynamic logic that runs in response to events like clicks or page loads.

HTML

Structure — what exists and what it means (headings, paragraphs, buttons, images).

CSS

Presentation — colours, spacing, fonts, layout: how the structure looks.

JavaScript

Behaviour — what happens on interaction: clicks, form validation, animations.

Concept 05

Environment Setup

Install these in order. Do not skip the --version checks — that step is what proves the terminal can actually "see" the tool you just installed.

  1. VS Code or Cursor — your code editor
  2. Live Server + Prettier extensions inside the editor
  3. Node.js LTS — lets JavaScript run outside the browser
  4. Git — tracks changes to your code over time
  5. GitHub account — remote home for your Git repositories
  6. Run all --version checks to confirm everything installed correctly

Editor extensions explained

ExtensionWhy you need it
Live ServerServes your HTML file over a real local address (http://127.0.0.1:5500) with auto-reload on save.
PrettierAutomatically formats your code on save so it stays clean and consistent.
ESLintWarns you about JavaScript mistakes — used more from later weeks onward.
Auto Rename TagWhen you rename an opening HTML tag, it automatically renames the matching closing tag too.

Verify Node and Git

// Run each line in your terminal and check the output
node --version         // expect v20.x.x or newer
npm --version          // expect 10.x.x or newer
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git --version
Layman's example

Checking --version is like turning the key in a car after installing a new battery — you don't assume it works, you actually start the engine and listen for it.

Technical definition

node is the JavaScript runtime, npm is its package manager, and git is your version-control tool. Each ships its own CLI, and checking its version confirms it's correctly on your system's PATH.

Common trap If a command prints command not found, close and reopen your terminal first (it often just hasn't reloaded your PATH yet) before assuming the install failed.
Concept 06

Your First HTML Page — Fully Annotated

Create a folder called hello-web containing a file called index.html:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Hello Web</title>
</head>
<body>
  <h1>Hello, Web Engineering</h1>
  <p>My name is <strong>Your Name</strong> and this is my first page.</p>
  <button id="greet">Click me</button>

  <script>
    document.getElementById("greet").addEventListener("click", () => {
      alert("The button works.");
    });
  </script>
</body>
</html>

Every part explained

<!DOCTYPE html>
Tells the browser: "this document follows the HTML5 standard." Always the first line.
<html lang="en">
The root element wrapping the whole page. lang tells screen readers and search engines which language the content is in.
charset="UTF-8"
Makes sure special characters (accents, symbols, emoji) display correctly instead of turning into garbled text.
viewport meta
Tells mobile browsers to scale the page to the device's actual screen width instead of shrinking a desktop-sized layout.
<title>
The text shown in the browser tab — not on the page itself.
<h1>, <p>, <strong>
Structural HTML tags: a top-level heading, a paragraph, and bold/important inline text.
<button id="greet">
A clickable element. The id is a unique name JavaScript uses to find this exact element on the page.
<script>
Where JavaScript lives. Here it listens for a click on the button and shows an alert popup.

Serving it correctly

Layman's example

Opening a file with file:// is like reading a printed menu at home — it looks right, but the restaurant kitchen (the server) isn't actually involved, so anything that needs the kitchen (like fetching live data) simply won't work.

Technical definition

Right-click the file → Open with Live Server. This serves it at a real address like http://127.0.0.1:5500/hello-web/index.html, using an actual local web server instead of the browser reading a raw file from disk.

Important — never do this Do not open the file by double-clicking it (that loads it as file:///C:/Users/.../index.html). Many browser features (fetch requests, modules, some storage APIs) silently break under file://. Always use Live Server so the address bar starts with http://.
BadGood
file:///C:/Users/.../index.html — some features break laterhttp://127.0.0.1:5500/... — real website behaviour
Concept 07

DevTools Tour

Open with F12 or Ctrl+Shift+I (Cmd+Option+I on Mac).

TabUse it for
ElementsSee and live-edit the page's HTML/CSS. Edits are temporary — reloading the page throws them away, because you're only editing the browser's in-memory copy (the DOM), not the actual file on disk.
ConsoleSee JavaScript errors, run console.log() output, and type quick JS commands directly.
NetworkSee every request the page made, its status code, size, and timing.
ApplicationInspect localStorage, cookies, and cache — covered in later weeks.
Layman's example

The Network tab is like a receipt showing every item the kitchen sent out and whether each one arrived fine. The Console tab is like a complaint log — if something went wrong in the kitchen, it's written there. The Elements tab is like rearranging the table decorations by hand — as soon as the table is reset (page reload), your changes are gone.

Technical definition

Elements shows the live DOM tree, not the source file. Console is a JS REPL plus error/log output stream. Network lists every HTTP request/response with method, status, size and timing waterfall.

Quick check Reload your page → open Network → find index.html → its status should read 200. Then open Console, type document.title, and press Enter — it should print the text from your <title> tag.
Reference

Full Glossary — Every Term Defined

Every technical word used in this topic, in one place.

Client
The program that makes a request — in web contexts, your browser.
Server
A computer (usually remote) that listens for requests and sends back responses.
Database
Where a server stores and retrieves persistent data (e.g. MongoDB).
HTTP
HyperText Transfer Protocol — the rules browsers and servers use to talk to each other.
HTTPS
HTTP encrypted with TLS/SSL, so data can't be read or tampered with in transit.
Request
A message the client sends asking the server to do something (read, create, update, delete).
Response
The message the server sends back, including a status code and often a body (HTML/JSON/etc).
DNS
Domain Name System — translates a human-readable domain (example.com) into a machine IP address.
IP address
A numeric address identifying a specific computer on a network.
Protocol
The agreed "language" used to communicate, e.g. http or https.
Host
The domain name / address of the server you're talking to.
Port
A numbered "door" on a computer that a specific service listens on (80 = HTTP, 443 = HTTPS).
Path
The part of the URL identifying which specific resource you want on that server.
Query string
Key-value pairs after ? in a URL, used to pass extra parameters; & joins multiple.
Fragment
The part after #; used only by the browser (e.g. to scroll to a section) and never sent to the server.
HTTP method
The verb of a request: GET, POST, PUT, PATCH, DELETE, etc.
Status code
A 3-digit number in the response describing the outcome (2xx success, 3xx redirect, 4xx client error, 5xx server error).
HTML
HyperText Markup Language — defines the structure and meaning of a web page's content.
CSS
Cascading Style Sheets — defines how the page looks (colour, layout, spacing, fonts).
JavaScript
The programming language that adds interactivity/behaviour to a web page.
DOM
Document Object Model — the browser's live, in-memory tree representation of the page's HTML.
Live Server
A VS Code extension that serves your folder over a real local HTTP address with auto-reload.
localhost / 127.0.0.1
Addresses that mean "this same computer" — used for local development servers.
Node.js
A runtime that lets JavaScript run outside the browser, e.g. on a server or in your terminal.
npm
Node Package Manager — installs and manages JavaScript libraries/packages.
Git
A version-control tool that tracks changes to your code over time.
GitHub
A website that hosts Git repositories remotely and enables collaboration.
Prettier
A code editor extension that auto-formats your code on save.
ESLint
A code editor extension that flags likely JavaScript mistakes as you type.
DevTools
The browser's built-in developer panel (Elements, Console, Network, Application, etc).
Console
The DevTools tab showing JS errors, logs, and a live JS command line.
Network tab
The DevTools tab listing every HTTP request the page made, with status and timing.
Elements tab
The DevTools tab showing the live DOM — editable, but never saved back to your file.
Application tab
The DevTools tab for inspecting localStorage, cookies, and cache.

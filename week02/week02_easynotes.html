Concept 01

The HTML Document Skeleton

Layman's example

Every house you build starts with the same foundation and frame, no matter what the house looks like later. HTML pages are the same — every single one starts with the exact same skeleton before you add any real content.

Technical definition

Every valid HTML5 document needs a <!DOCTYPE html> declaration, a root <html> element, a <head> for metadata, and a <body> for visible content.

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8"/>
    <meta name="viewport" content="width=device-width, initial-scale=1.0"/>
    <meta name="description" content="A short page summary for search engines."/>
    <title>My Profile</title>
  </head>
  <body>
    <h1>Hello</h1>
    <p>This is my first paragraph.</p>
  </body>
</html>
<!DOCTYPE html>
Declares the document as HTML5.
<html>
The root element of the page.
<head>
Information about the page — not shown on screen.
<title>
Text shown in the browser tab.
<body>
All visible content.
<h1>
A large top-level heading.
<p>
A paragraph.
Don't forget these two Forgetting charset="UTF-8" can make special characters look broken. Forgetting viewport makes the page look tiny and unusable on phones.
Concept 02

HTML Elements & Attributes

Layman's example

An element is like a labelled box: a start tag is the "open" flap, the content is what's inside, and the end tag is the "close" flap. An attribute is like a sticky note on the outside of the box giving extra instructions — "fragile", "this side up".

Technical definition

An element is <tagname>content</tagname>. Attributes are key="value" pairs inside the start tag that give the browser extra information about that element.

<h1>My First Heading</h1>
<p>My first paragraph.</p>
<a href="https://example.com" target="_blank">Visit site</a>
Start tagContentEnd tag
<h1>My First Heading</h1>
<p>My first paragraph.</p>
<a>Visit site</a>
Empty (void) elements Some elements have no content and no end tag: <img>, <br>, <hr>, <input>, <meta>, <link>. They're self-contained — nothing goes "inside" them.

Attributes in action: href tells a link where to go; target="_blank" tells it to open in a new tab.

Concept 03

Headings & Text

Headings

<h1>This is heading 1</h1>
<h2>This is heading 2</h2>
<h3>This is heading 3</h3>
Layman's example

Headings are like the outline of a book: Chapter title (h1), section title (h2), sub-section title (h3). You'd never jump from a chapter title straight to a sub-sub-section — the outline would stop making sense.

Technical definition

<h1> through <h6> define a hierarchy of importance. Use exactly one <h1> per page (the page title), and never skip a level (no jumping h1 → h3).

Paragraphs & inline emphasis

<p>
  <strong>Important text</strong> and
  <em>emphasized text</em>.
</p>
TagUse
<p>A paragraph
<strong>Important text — usually renders bold
<em>Emphasized text — usually renders italic
Concept 04

Lists

Layman's example

A grocery list where order doesn't matter (milk, eggs, bread) is an unordered list. A recipe's numbered steps, where order matters, is an ordered list. A dictionary — word, then its meaning — is a description list.

Technical definition

<ul> = bullet list, <ol> = numbered list, both containing <li> items. <dl> pairs <dt> (term) with <dd> (definition).

<ul>
  <li>Coffee</li>
  <li>Tea</li>
  <li>Milk</li>
</ul>

<ol>
  <li>Open the editor</li>
  <li>Create a file</li>
  <li>Save the file</li>
</ol>

<dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>
  <dt>CSS</dt>
  <dd>Cascading Style Sheets</dd>
</dl>
TagUse
<ul>Bullet list — order does not matter
<ol>Numbered list — order matters
<li>One list item
<dl> / <dt> / <dd>Term and its definition
Concept 05

Links

HTML links are defined with the <a> tag. The href attribute is the destination.

<!-- Link to another page -->
<a href="about.html">About us</a>

<!-- Link to another website -->
<a href="https://www.w3schools.com" target="_blank" rel="noopener noreferrer">
  Visit W3Schools
</a>

<!-- Jump to a section on the same page -->
<a href="#contact">Contact</a>

<!-- Email and phone -->
<a href="mailto:me@example.com">Email me</a>
<a href="tel:+923001234567">Call me</a>
Attribute / patternMeaning
href="page.html"Link to another file
href="https://..."Link to an external site
href="#id"Jump to an element with that id
target="_blank"Open in a new tab
rel="noopener noreferrer"Safer new-tab links — always pair with target="_blank"
Layman's example

Opening a link in a new tab without rel="noopener" is like handing a stranger a copy of your house key along with the address — the new page could, in rare cases, reach back and mess with your original tab. noopener takes the key back.

Technical definition

noopener stops the newly opened page from getting a JS reference back to your original tab (security). noreferrer also hides your site's URL from the destination's analytics (privacy). Neither affects SEO — search engines crawl and pass link authority through these normally.

Concept 06

Images

HTML images use the <img> tag — an empty element with no end tag.

<img
  src="images/me.jpg"
  alt="A student smiling in front of a laptop"
  width="400"
  height="400"
/>
AttributeMeaning
srcPath or URL of the image
altText shown if the image fails to load, and read aloud by screen readers — required
width / heightSize in pixels — helps stop the page "jumping" while the image loads
loading="lazy"Only loads the image once it's near the visible screen
Writing good alt text Describe what the image actually shows, e.g. alt="A student smiling in front of a laptop". If the image is pure decoration with no meaning, use an empty alt="" so screen readers skip it.

Image with a caption

<figure>
  <img
    src="images/project.png"
    alt="Screenshot of a to-do app on a laptop"
    width="800"
    height="450"
  />
  <figcaption>My Week 01 hello page on Live Server</figcaption>
</figure>

<figure> groups an image with its caption; <figcaption> is the caption text itself.

Concept 07

Semantic Elements

Layman's example

Imagine labelling every box in your house "box" — you'd have no idea which one has kitchen stuff and which has clothes. Semantic tags are like writing the real label on each box: "Kitchen", "Living Room", "Bedroom" — anyone (including a screen reader) instantly knows what's inside.

Technical definition

Semantic elements describe their meaning, not just their appearance, unlike a generic <div>. Browsers, search engines, and assistive technology all use this meaning.

Bad — no meaning

<div class="header">...</div>
<div class="nav">...</div>
<div class="content">...</div>
<div class="footer">...</div>

Good — semantic

<body>
  <header>
    <h1>My Site</h1>
    <nav>
      <ul>
        <li><a href="profile.html">Home</a></li>
        <li><a href="contact.html">Contact</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h2>About me</h2>
      <p>I am learning web engineering.</p>
      <section id="skills">
        <h3>Skills</h3>
        <ul>
          <li>HTML</li>
          <li>CSS</li>
        </ul>
      </section>
    </article>

    <aside>
      <h2>Currently learning</h2>
      <p>JavaScript</p>
    </aside>
  </main>

  <footer>
    <p>&copy; 2026 My Site</p>
  </footer>
</body>
<header>Introductory content
<nav>Navigation links
<main>Main content — one per page
<article>Content that makes sense alone
<section>A thematic group, usually with a heading
<aside>Side content — related links, tips
<footer>Footer for the page or section
<div>Use only when no better semantic tag exists
Concept 08

Forms

Layman's example

A form is a paper application form come to life: blank fields for you to fill in (name, email), checkboxes to tick, a dropdown of pre-set choices, and a "Submit" button that hands the completed form to whoever's collecting it.

Technical definition

An HTML form collects user input. The <form> element wraps a set of <input>, <select>, and <textarea> controls and, when submitted, sends their values to a server.

<form action="#" method="post">
  <label for="name">Full name</label>
  <input type="text" id="name" name="name" required/>

  <label for="email">Email</label>
  <input type="email" id="email" name="email" required/>

  <button type="submit">Send</button>
</form>
PartMeaning
<form>Container for inputs
actionWhere to send the data — a server URL
methodUsually get or post
<label for="id">Label linked to an input with a matching id
nameName of the value when the form is submitted
requiredBrowser blocks an empty submit
Non-negotiable rule Every <input> needs a <label> (with a matching for/id pair) and a name. Without a matching for/id, clicking the label text won't focus the field — and without name, the value never gets submitted at all.

Input types

text

Normal text field

email

Checks email format + shows email keyboard on phones

password

Hides typed characters

tel

Shows phone keypad on phones

number

Number-only field

date

Native date picker

url

Checks URL format

file

Upload a file

checkbox

On/off option

radio

Choose one option from a group

submit

Submits the form

Full contact form example

<form action="#" method="post">
  <div>
    <label for="name">Full name</label>
    <input type="text" id="name" name="name" required autocomplete="name"/>
  </div>

  <div>
    <label for="email">Email</label>
    <input type="email" id="email" name="email" required
      placeholder="you@example.com"/>
  </div>

  <div>
    <label for="phone">Phone</label>
    <input type="tel" id="phone" name="phone"/>
  </div>

  <fieldset>
    <legend>Preferred track</legend>
    <label><input type="radio" name="track" value="frontend"/> Frontend</label>
    <label><input type="radio" name="track" value="backend"/> Backend</label>
  </fieldset>

  <div>
    <label for="topic">Topic</label>
    <select id="topic" name="topic">
      <option value="">Choose one</option>
      <option value="help">Help</option>
      <option value="feedback">Feedback</option>
    </select>
  </div>

  <div>
    <label for="message">Message</label>
    <textarea id="message" name="message" rows="4"></textarea>
  </div>

  <label>
    <input type="checkbox" name="terms" required/>
    I accept the terms
  </label>

  <button type="submit">Send</button>
</form>
<textarea>
Multi-line text input.
<select> + <option>
A dropdown of choices.
<fieldset> + <legend>
Groups related controls (e.g. a set of radio buttons) with a group title.
placeholder
A grey hint shown inside an empty field — it disappears on typing and is not a substitute for a real <label>.
Concept 09

Tables

Golden rule Use <table> for tabular data only — grades, prices, schedules. Never use a table just to lay out a page's boxes; that's what CSS is for (Week 03). 
<table>
  <caption>My tools</caption>
  <thead>
    <tr>
      <th scope="col">Tool</th>
      <th scope="col">Comfort</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">HTML</th>
      <td>Strong</td>
    </tr>
    <tr>
      <th scope="row">CSS</th>
      <td>Beginner</td>
    </tr>
  </tbody>
</table>
TagMeaning
<table>The table itself
<caption>Table title
<thead> / <tbody>Header section vs. body section
<tr>Table row
<th>Header cell
<td>Data cell
scope="col" / scope="row"Tells assistive tech what the header describes
Concept 10

id, class & Comments

Layman's example

An id is like a person's national ID number — exactly one per person, never shared. A class is like a job title — many people can share "Teacher", and one person can hold several titles at once.

Technical definition

id and class name elements so you can link to them, style them with CSS (Week 03), or find them with JavaScript later.

<h2 id="skills">My Skills</h2>
<p class="bio">I am learning web engineering.</p>
<p class="bio highlight">HTML is my favorite so far.</p>

<a href="#skills">Jump to skills</a>
AttributeRuleUse
idMust be unique on the pageOne specific element — #skills
classCan be reused on many elementsA group of similar elements — .bio
Many classesSeparate with a spaceclass="bio highlight"
Naming convention id names should not start with a number. Prefer lowercase-with-hyphens: contact-form, not Contact Form.

Comments

HTML comments are never shown in the browser — use them as notes for yourself while building.

<!-- This is a comment -->
<!-- Main profile content starts here -->
<article>
  <h2>About me</h2>
</article>
Security reminder Never put secrets or passwords in comments — anyone can right-click → View Source and read them.

Reference

Full Glossary — Every Term Defined

Element
A start tag, its content, and its end tag together — the basic building block of HTML.
Attribute
A key="value" pair inside a start tag that gives extra information about that element.
Empty / void element
An element with no content and no end tag, e.g. <img>, <br>, <input>.
Semantic element
A tag that describes its own meaning, e.g. <header>, <nav>, <article>.
alt text
Descriptive text on an <img>, shown if the image fails and read by screen readers.
Form
An HTML structure (<form>) that collects user input and submits it, usually to a server.
Label
Text (<label>) describing an input; linked via matching for/id.
Placeholder
A hint shown inside an empty input field — disappears on typing, not a replacement for a label.
Fieldset / legend
A box (<fieldset>) that groups related form controls, with a title (<legend>).
id
A unique identifier for one specific element on a page.
class
A reusable identifier that can be shared across many elements.
HTML comment
Text between <!-- and -->, never shown in the browser.
Validator
A tool (e.g. validator.w3.org) that checks your HTML follows the spec correctly.
rel="noopener noreferrer"
Link attribute that improves security and privacy for links opened in a new tab.
scope (table)
Attribute on <th> telling assistive tech whether the header describes a column or a row.
Self-Check

Before Week 03

  • I can write a basic HTML document from memory.
  • I know when to use article, section, aside, vs. plain div.
  • Every image on my page has a meaningful alt.
  • Every input on my page has a label and a name.
  • I know the difference between id and class.
  • My page passes the W3C validator with zero errors.

Class Activity D

15 min · contact form
Task

Build an accessible contact form

Add a Contact section with a form with all the below inputs:
  • text, email, tel
  • select
  • textarea
  • checkbox
  • submit button
Then test:
  1. Remove one for/id pair → label click should fail
  2. Put it back
  3. Submit empty → browser should block because of required
Done when: every label focuses its field.
Model answer 
<section id="contact">
  <h2>Contact</h2>
  <form action="#" method="post">
    <div>
      <label for="name">Full name</label>
      <input type="text" id="name" name="name" required />
    </div>

    <div>
      <label for="email">Email</label>
      <input type="email" id="email" name="email" required placeholder="you@example.com" />
    </div>

    <div>
      <label for="phone">Phone</label>
      <input type="tel" id="phone" name="phone" />
    </div>

    <div>
      <label for="topic">Topic</label>
      <select id="topic" name="topic">
        <option value="">Choose one</option>
        <option value="help">Help</option>
        <option value="feedback">Feedback</option>
      </select>
    </div>

    <div>
      <label for="message">Message</label>
      <textarea id="message" name="message" rows="4"></textarea>
    </div>

    <label>
      <input type="checkbox" name="terms" required />
      I accept the terms
    </label>

    <button type="submit">Send</button>
  </form>
</section>

Testing note: if you temporarily change for="email" to for="emial" (typo), clicking the "Email" label text will no longer focus the field — proving the for/id match is what makes labels clickable.

Homework — Task 1

Semantic teardown
Task

Label a real homepage's semantic regions

Screenshot any real homepage. Draw boxes and label: header, nav, main, article, aside, footer.
Submit: annotated image.
Model answer — how to identify each region
  • header — the top strip with the logo and main navigation
  • nav — the menu links, often inside the header
  • main — the central, page-specific content area
  • article — a self-contained block within main, e.g. a news story or product card
  • aside — sidebars: related links, ads, "you might also like"
  • footer — the bottom strip with copyright, social links, sitemap

Homework — Task 2

Fix bad HTML
Task

Rewrite div-soup as semantic HTML

Rewrite this in homework-rewrite.html using semantic tags:
<div class="top">
  <div class="big-text">My Blog</div>
  <div class="links"><span onclick="go('/')">Home</span></div>
</div>
<div class="post">
  <div class="post-title">First Post</div>
  <div class="post-body">Hello world</div>
  <div class="date">Aug 9 2026</div>
</div>
Submit: file that passes the W3C validator.
Model answer — semantic rewrite 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My Blog</title>
</head>
<body>
  <header>
    <h1>My Blog</h1>
    <nav>
      <ul>
        <li><a href="/">Home</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h2>First Post</h2>
      <p>Hello world</p>
      <p><time datetime="2026-08-09">Aug 9 2026</time></p>
    </article>
  </main>
</body>
</html>

What changed and why: the <span onclick="go('/')"> becomes a real <a href="/"> — links should be actual <a> tags, not clickable <span>s, so they work with keyboards and screen readers. Each generic <div> becomes the tag matching its real meaning: title→<h1>/<h2>, the post itself→<article>, the date→<time>.

Where did you almost use a <div>?

In up to 5 sentences: describe one spot where you almost reached for a plain <div>, and what semantic tag you used instead.
Model answer (example — write your own)

I almost wrapped my "Currently learning" note in a plain <div>, but since it's related-but-secondary content next to my main bio, I used <aside> instead. That was a better fit because <aside> tells the browser and screen readers this content is supplementary, not part of the main flow of the article, which a generic <div> could never communicate.
